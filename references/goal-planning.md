# 按整理目标规划

当用户因只有 C 盘而希望先建数据盘再搬家时使用。先明确整理目标，不能仅因 C 盘当前空闲少就反复推荐清理或直接认定必须加硬盘。

## 数据与容量

- 从同一原用户、24 小时内的有效体检选择尚未处理的搬家项目；用户未确定目标时先展示项目，请其选择。只搬系统登记的用户文件夹和可靠识别的聊天数据。已安装软件、系统文件、开发环境、未知 AppData 不能视为可直接搬的数据。
- 下限大小不能证明能装下；未知或下限项目先重新体检核实。持续无法取得可靠大小时明确无法保证，不执行该项搬家，也不把下限换成精确值。聊天与文档避免重复计量，先聊天，再重新体检父文件夹。
- 新分区容量受当前空闲、Windows 可压缩量和现有保留策略共同限制。默认仍保留 max(已用 + 60 GB, 120 GB)，这是本技能的保守策略，不是 Windows 的固定技术要求。不得因用户想搬家而自行减为 30 GB 等固定值，或把未来释放量算入当前可压缩容量。
- 每个完整项目需要实际大小的 110% 容量；多项目同时保留原件时累计计算目标占用。复制期间源和目标各存一份，新增与增长仍可能令估算不足。运行前脚本重新核实真实容量，估算不覆盖执行安全检查。

## 规划输入与结果

在 `partition.ps1 -Plan` 的 `-Layout` JSON 中可附带 `MigrationItems`，例如：

```json
{"Count":1,"MigrationItems":[{"Id":"move:KnownFolder:Downloads","Bytes":10737418240,"IsLowerBound":false}]}
```

AI 从有效体检填值，不让用户编辑 JSON。这个字段仅作建议估算，不参与磁盘执行授权或搬家动作。不能伪造精确值。未提供目标时不称“分区足以完成搬家”。已有数据盘优先按新体检 DataVolumes 检查实际剩余量，不用新建分区估算代替。

`CapacityAssessment`：`PolicyUsableBytes` 是保留策略允许划出的上限，`WindowsMaxShrinkBytes` 是 Windows 上限（null 表示未知）；`LimitingFactor` 区分 ReservePolicy、WindowsShrinkLimit、Both、WindowsLimitUnknown、Unknown。Windows 上限未知时只能给条件性方案，不称技术检查已通过。`RequiredCBytes` 是当前策略要求的 C 盘大小。不能把未提权读取不到的值说成零。

`MigrationAssessment`：`RequiredBytes` 含 10% 余量，`CapacityBytes` 是新分区总容量，`ShortfallBytes` 仅表示总容量差额。`Assignments` 和 `RemainingIds` 是按完整项目保守分配的结果，可能因单项目太大或多个盘容量分布而无法装下，即使总差额为零也不能称全部能搬。该估算未减去新卷文件系统开销，实际可用量必须在分区后重新体检核实。

| 状态 | 说明与下一步 |
| --- | --- |
| Full | 估算能容纳目标项目；展示容量方案、C 盘剩余和限制，经方案二次确认才分区。分区成功后重新体检，再逐项确认搬家。 |
| Partial | 展示能装入和仍留 C 盘的项目；先问是否接受部分整理，不默认扩大目标。不承诺以后扩容已有数据分区。 |
| NoFit / NoDestination | 当前方案不能容纳完整目标项目或没有新数据盘；解释策略/技术限制和容量缺口，评估独立外部中转或增加内部硬盘，不反复要求无收益清理。 |
| SizeUnknown / NoTargets | 尚不能判断目标能否完成，先核实大小或目标；不为了补字段执行搬家或分区。 |

## 分阶段与边界

先建小数据盘并搬入部分项目可以是最终的部分整理方案，但不是自动扩容方案。C 盘再次缩小的空闲区域往往位于 D 盘左侧，Windows 通常不能直接用它扩展 D 盘。本技能仍不移动、删除、合并或扩容已有分区；不承诺可以靠反复压缩完成全部搬家。

外部中转需另行制定并确认备份、复制校验和最终布局方案；当前搬家入口仅支持固定 NTFS 数据盘，不能直接调用它向移动硬盘搬家。不能自动删除 D 盘重建，不能把同盘副本算作备份。用户希望突破默认保留策略时，解释当前实现边界，另行设计并验证策略；不暗改阈值。

分区、搬家、释放原件分别授权。试用确认之前不得删除原件；当前请求只授权修改 skill 时，不能顺带实际改盘。
